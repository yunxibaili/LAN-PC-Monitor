## 七、CI 修复记录（发布前质量门槛）

### 背景

GitHub Actions `Windows Tests`（3.10/3.11 矩阵）首次在 main 上运行（此前 commit 未推送），两个问题：

### 问题 1：check_env UTF-8 崩溃（已修复，commit `307c6d3`）

- **现象**：`Environment check` 步骤 1 秒失败。
- **根因**：Windows runner 捕获输出为 cp1252，`tools/check_env.py` 打印中文 → `UnicodeEncodeError`。
- **修复**：workflow job 级 `env: PYTHONUTF8: "1"` + `PYTHONIOENCODING: "utf-8"`；并 `fail-fast: false` 让矩阵两腿独立报告。
- **验证**：check_env 步骤双腿 success。

### 问题 2：Agent 在无 AMD 机器上启动即崩（已修复，见下）

- **现象**：`Run test_api` 步骤 2 秒失败（Agent 子进程秒退）。
- **根因**（CI 日志铁证）：`common/collectors/gpu_collector.py` 的 pyadl import 保护只捕获 `ImportError`，但 pyadl 在无 AMD 驱动时于 import 阶段直接抛自定义 `ADLError("Driver not found!")` → 模块导入崩溃 → Agent 启动即崩。
  - 本机 3.12 未安装 pyadl（走 ImportError 降级）→ 本地无法复现；本机 3.11 装有 AMD ADL DLL（import 成功）→ 也无法复现；CI（无 AMD）→ 必现。
- **修复**：`except ImportError` → `except Exception`（导入失败即视为无 ADL，降级 N/A，与模块 docstring "无 GPU 或库不可用：全 N/A，不报错" 一致）。
- **验证**：本地 3.12 全量回归 988/988；3.12/3.11 test_api 14/14；CI 复跑待确认。

### 后续

- CI 绿后创建 GitHub Release v5.2.3（tag `v5.2.3-release`，内容见 `docs/releases/v5.2.3.md`）。
- netifaces 无 cp310+ wheel 问题已登记为 #7（P2/v5.3），不阻塞本次发布（3.10/3.11 在 runner 上有 MSVC 可编译）。
