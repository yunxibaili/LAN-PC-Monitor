# v5.2 Host UI 重构 — 迁移计划

> **Version**: v5.2（迁移计划）
> **Status**: Plan
> **基线**: v5.1 已实现代码（`host/gui/main_window.py` 732 行、`common/config_manager.py`、`host/connection_core.py`、`host/alerts.py`）
> **目标**: 将 v5.1 单一大窗口迁移到 v5.2 多页面 + Store 架构，不破坏 monitor_data 协议 / REST API / 采集器
> **配套**: [v52_ui_design_legacy.md](v52_ui_design_legacy.md)（设计）、[v52_architecture_review.md](v52_architecture_review.md)（评审）

---

## 一、迁移总原则

1. **增量迁移，不重写**：v5.1 的 `NodeConnection` / `connection_core` / 采集器 / `AlertEngine` 全部保留，只重构 Host UI 层。
2. **先拆后画**：先建 `store/` 骨架与 Facade，确认数据流后再开发页面组件，避免返工。
3. **每阶段可运行**：每完成一个阶段，Host 仍能启动、连接节点、显示数据。
4. **信号驱动优先**：沿用 v5.1 的"数据到达即更新"模式，不引入 QTimer 轮询（评审 §2/§4 结论）。

## 三、关键 Facade / Adapter / Manager 设计

### 3.1 SettingsFacade（配置入口）

**现状**：`common/config_manager.py` 已有 `ConfigManager`（46 个方法，含 `SettingsManager` 别名），`main_window` 直接持有 `self.cfg` 字典。

**迁移**：
```
v5.1: self.cfg["language"] = "zh_CN"; host_config.save_config(self.cfg)
      ↓
v5.2: SettingsFacade.set("language", "zh_CN")   # 内部走 SettingsManager
      SettingsFacade.get("theme")                # 默认值兜底
```

| 职责 | 说明 |
|------|------|
| 包装 `SettingsManager`，提供 `get/set/reset` 统一入口 | 页面不直接碰字典 |
| 变更通知信号 `settings_changed(key)` | 页面响应式更新 |
| 默认值兜底 | 新字段（theme/ui_scale/chart_refresh_ms 等）缺失时返回默认 |
| 持久化 | 保存到 agent_config.json + host_config.json |

**新增字段**（评审 §5）：`ws_read_timeout`、`reconnect_interval`、`chart_refresh_ms`、`history_minutes`、`alert_dedup_seconds`。

### 3.2 ViewModel / FrameStore（数据读取）

**现状**：`self.frames[node_id]` 直接由 `_on_data` 写入，UI 直接读 dict。

**迁移**：
```
v5.1: MainWindow._on_data -> self.frames[node_id] = frame -> UI 直接读
      ↓
v5.2: ConnectionCore.on_data -> FrameStore.push(node_id, frame)
      FrameStore.frame_updated = Signal(node_id, frame)   # 变更信号
      页面: FrameStore.get(node_id) 读最新帧；订阅 frame_updated 增量刷新
```

| Store | 数据 | 信号 |
|-------|------|------|
| `FrameStore` | `frames[node_id]` 最新帧 | `frame_updated(node_id, frame)` |
| `HistoryStore` | `history[node_id]` deque(300) | `point_added(node_id, metric, value)` |
| `NodeStore` | 连接/状态/RTT/丢包/评分 | `node_status_changed(node_id, status)` / `metrics_updated` |
| `AlertStore` | 告警列表 + 计数 | `count_changed(count)` / `alert_added(alert)` |

### 3.3 AlertAdapter（告警去重桥接）

**现状**：`AlertEngine.check(frame)` 每帧执行，`_alert_state` 按"上一次 red/warn"去重弹窗。

**迁移**：
```
v5.1: _check_alerts -> AlertEngine.check -> _alert_state 去重 -> 状态栏/托盘
      ↓
v5.2: FrameStore.frame_updated -> AlertService.evaluate(node_id, frame)
      -> AlertEngine.check -> AlertStore.push(alert)   # 30s 窗口去重（评审 §8.4）
      -> AlertAdapter 消费：状态栏 / 托盘气泡 / AlertsPage 表格 / SideNav 徽标
```

**去重策略变更**（评审 §8.4）：v5.1 是状态变化去重，v5.2 改为时间窗口去重（同一 `node_id+path` 30s 内只记一次）——需在 AlertStore 增加 `_last_alert_time` 字典。

### 3.4 TrayManager（托盘独立）

**现状**：`_init_tray` 内联在 main_window，仅作告警气泡。

**迁移**：
```
v5.1: MainWindow._init_tray() 内联
      ↓
v5.2: TrayManager(window)
      - init()         创建 QSystemTrayIcon
      - show_alert()   托盘气泡（订阅 AlertStore）
      - menu           打开/显示主窗口、退出（最小化到托盘，评审 §8.1）
      - close_hook()   window.closeEvent 时隐藏而非退出
```

## 四、分阶段迁移步骤

### Phase 0 · 基础设施（半天）

- 建 `host/store/` 包：`node_store.py` / `frame_store.py` / `history_store.py` / `alert_store.py`
- 建 `host/facade/`：`settings_facade.py` / `alert_adapter.py`
- 建 `host/manager/`：`tray_manager.py` / `discovery_service.py`
- **验证**：纯 Python 单测（无 PyQt5）—— Store 的 push/get/信号 逻辑

### Phase 1 · 配置 + 数据层接入（1 天）

- `main_window` 的 `self.cfg` → `SettingsFacade`
- `_on_data` 写入 `FrameStore`；`_on_status/_on_rtt/_on_loss` 写入 `NodeStore`
- 页面仍用旧 UI（main_window 直接读 Store），确认数据流不变
- **验证**：Host 启动、连接节点、数据更新正常（等价 v5.1 行为）

### Phase 2 · 告警 + 托盘解耦（1 天）

- `_check_alerts` → `AlertService` + `AlertStore` + `AlertAdapter`
- `_init_tray` → `TrayManager`
- **验证**：告警仍状态栏+托盘；托盘最小化到托盘正常

### Phase 3 · 页面拆分（3 天）

- `_build_ui` 拆为 `SideNav` + `QStackedWidget`（5 页面占位）
- 迁 `OverviewGrid` → `DashboardPage`（NodeCard 重构，评审 §8.6）
- 迁节点列表/详情 → `NodesPage` + `NodeDetailPanel`
- **验证**：导航切换正常，页面从 Store 读数据

### Phase 4 · 新页面（4 天）

- `MonitorPage`（6 仪表卡 + 折线/面积/柱状，pyqtgraph）
- `AlertsPage`（表格 + 统计卡片，读 AlertStore）
- `SettingsPage`（5 Tab，走 SettingsFacade）
- **验证**：各页数据正确，告警页实时更新

### Phase 5 · 集成 + 性能（2 天）

- 移除 main_window 残留状态（nodes/frames/... 全走 Store）
- 性能基准：16 节点 / 50 节点 / 24h 内存
- 回归：test_api 14/14、test_p0 42/0/3

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| main_window 732 行拆解时遗漏状态引用 | 运行时 KeyError | Phase 1-2 保持旧 UI，逐属性替换并跑测试 |
| Store 信号跨线程 | UI 卡顿/崩溃 | 沿用 Qt 信号（ConnectionCore 回调 → emit → 主线程 slot），不直接跨线程改控件 |
| 告警去重语义变化（状态→时间窗口） | 用户感知告警频率变化 | 文档明示；默认 30s 窗口合理 |
| 50 节点图表卡顿 | 性能不达标 | 图表降采样 + 不可见页暂停订阅 + 增量 setData（评审 §7） |
| scorers 迁移 | QualityScorer 有状态（deque） | 保留在 NodeStore 内为 `dict[node_id→QualityScorer]`，不散落 |
